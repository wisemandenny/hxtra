# Snapshots

The snapshot manager and its records, select, its callers, the snapshot footswitch mode and the snapshot icon. Status tags as in [conventions.md](../conventions.md).

- **The snapshot manager** is a static object at `0x2812c630` (`0x28d960a4()`). `+4` is its lock (`0x28e24c00` lock, `0x28e24bb0` unlock, called with `manager + 4`), and it holds **three 0x260-byte records inline** at `+0xc + 0x260 * i`. After them come 20 block-enable bytes at `+0x72c`, the controller count at `+0x741`, the footswitch-entry count at `+0x742`, the current snapshot at `+0x743`, the previous one at `+0x744` and a busy byte at `+0x9a9`. About 35 functions index the records with `mov #0x260; mla`, so the array can't grow in place.
- **A record**: block states at `+0x00..0x13`; controller entries, 7 bytes each, from `+0x28` (value at `+1`, count `+0x741`); footswitch entries, 9 bytes each, from `+0x1e8` (switch index, then the bytes `0x28de672c` writes into the footswitch manager `0x28d96094()` at `+0x81 + 7 * switch`; count `+0x742`); a valid byte at `+0x24b` (0 until the snapshot holds a sound); tempo at `+0x250`; the name at `+0x255` (11 bytes, default `SNAPSHOT n`). `0x28de14b4(manager, record, name)` writes a record's defaults and takes the lock itself. `0x28de12d4(manager, to, from, with_name)` copies one.
- **Select** `0x28de2f90(manager, index)`: returns 0 while `+0x9a9` is set, and does nothing for an index above 2. On a new index it stores the old one in `+0x744`. It then sets block states against the live DSP, sends every controller value, and writes the footswitch entries (it compares them with the old record's only to decide whether to refresh). An unused record (valid 0) is first filled from the old one (`0x28de12d4(..., 0)`, name kept). On the current index, setting **ID 103 Reselect Snapshot** decides: 0 recalls it again, otherwise it goes back to the previous one.
- **Snapshot Edits** [verified offline] (disassembly, and the handler run in unicorn with each setting, 2026-11-20; on the unit: [features/more-snapshots.md](../features/more-snapshots.md), a read in bank B): the manager's event handler (`0x28de20e8`, the manager's first word, called by the dispatcher `0x28d94ec8` at `0x28d94f50`) takes a block's on/off event at `0x28de23fa`. Unless select is under way (`+0x9a8`, set at `0x28de2fe0`, cleared by the request `{2, 0x0d}` at `0x28de21ca`) or the event's source is 4 (select's own), it reads setting **ID 73 Snapshot Edits** (0 Recall, the default, 1 Discard; strings at `0x28e25240`). On Recall it writes the new state into the current snapshot's record at once (`0x28de2578..0x28de2588`); on Discard it only sets a flag in that record (`0x28de2440..0x28de244e`), so the change lives only in the live blocks until a save. Snapshot-assigned controllers go the same way (`0x28de1e8c`). Select keeps no live state: it switches the blocks whose live state differs from the target record (`0x28de3056..0x28de30da`); the only record it writes is an unused target, filled from the record it leaves (`0x28de32b4`).
- **Snapshot footswitch mode** [verified on unit]: a press reaches select through the footswitch-function dispatcher `0x28dd14a0(state, switch)` (called with switch 0, 1, 2 at `0x28dd18d4`, `0x28dd18fa`, `0x28dd190c` by bits 0..2 of an event mask; function byte at `0x28128a74 + 2 * switch`, table at `0x28dd14e4`). Function 14 (`0x28dd16b0`) is snapshot k for footswitch k; 7 next and 8 previous (wrapping) share its tail call `b.w select` at `0x28dd1640`. Pressing the lit one calls select with the current index, which Reselect Snapshot then handles. Found with a probe image (MD5 `f025b397…`) that counted the hook's entries and every select: in that mode `0x28de59a8` was never reached.
- **Callers**: the footswitch snapshot action `0x28de59a8(fsw, switch, which)` reads an action byte at `fsw + 7 * switch + 0x81 + (which ? 2 : 3)`: 1 next, 2 previous, 3..5 snapshots 1..3, which it tail-calls at `0x28de59d8` (`b.w select`). Other callers: MIDI CC 69 in the CC handler `0x28d9b120(cc, value)` (0..2, 8 next, 9 previous; stock ignores 3..7) [verified offline], the HX Edit command `0x58` (`0x28e1bfc4`, registered at `0x28e1e2c0`), and the Copy/Swap Snaps menu (`0x28de17c0` copy, `0x28de1888` swap).
- **Locks** [verified offline] (disassembly, 2026-11-19; [features/more-snapshots.md](../features/more-snapshots.md) uses them):
  - The manager lock and D, the DSP model's lock, are the ROM's mutex (`0x28e24c00` → `0x100034bc` → `0x10000500`, unlock `0x28e24bb0` → `0x100005b4`; [home-screen.md](home-screen.md) has what it does with `CONTROL` 0). It is recursive: the owner's lock adds to a count (`0x10000560`). It has no timeout: a waiter sleeps until an unlock hands the mutex to the first waiter in the task list (`0x100005cc..0x10000614`). Nothing in it changes a task's priority, so there is no priority inheritance.
  - D is `0x28e07844(engine)`: the mutex at `[0x28449e78] + 8` for engine 0, address 8 for any other; `0x28e0785c(engine)` unlocks. The engine is `0x28d92a98()` (`[0x2844adcc]`), 0 on the unit: the boot stores it (`0x28d9334e`) from `0x28e02238`'s out argument, which `0x28e05c90` sets to 0 (`0x28e05c9a`), so D is `[0x28449e78] + 8`. With `[0x28449e78]` still 0, early in the boot, the lock writes at address 8. `0x28e05c90` makes the model once (a second call is refused at `0x28e05c98`): it stores the pointer, the static `0x28445740` (`0x28e05cb4`), then zeroes the model (`0x28e05cbc`) and makes the mutex (`0x28e05cc4`).
  - Select takes D, then the manager lock (`0x28e023a0` at `0x28de2fd0`, the lock at `0x28de2fd6`), and lets them go in the other order (the manager lock at `0x28de3274`, D through `0x28e02414` at `0x28de327c`; the other exits at `0x28de32cc`, `0x28de36d6`, `0x28de371c`). `0x28e023a0` takes D only while `[0x2843ebb8]` is 2 and the model's `+0x10` is 2 (`0x28e023b2..0x28e023c4`); it marks `model + 0x46d0`, which `0x28e02414` reads before it lets go. Otherwise select runs without D.
  - HX Edit's Get edit buffer (`0x28e1c55c`, command `0x16`) holds D from before the serializer until its reply is written: taken at `0x28e1c566`/`0x28e1c56a`, the serializer at `0x28e1c5b2`, then the TOC's second write (`0x28e1c5d4`) and the reply's writes under its stream's lock (`0x28e1c62c` to `0x28e1c670`), and `0x28e1c674` branches back to let D go at `0x28e1c5ba`/`0x28e1c5be`, where a failed serializer goes straight. It runs in the transport task, not the request task: `0x28d9964c` (the task's loop) → `0x28d9947c` → the editor service `0x28e16355` (vtable word at `0x28001f88`) → its call of the command at `0x28e16382` (`0x28e1c55d` is in the command table at `0x28e1e44c`).
  - Both serializers take D around their block copy (`0x28e0256c`, D at `0x28e02598`). A save holds the save lock `0x2822f528` (`0x28df25a4`: taken at `0x28df25b2`, let go at `0x28df2662`) around its two serializers, `0x28df2060` → `0x28deacf4` at `0x28df264e` and `0x28df2148` → `0x28dea8c4` at `0x28df265a`, each with its own D. `0x28df15a4` takes D and then, through `0x28df02fc` → `0x28df22f8`, the save lock, so stock has both orders of those two.
  - Loads parse under D. `0x28df22f8` (a preset change, `0x28dd17b0` → `0x28df02fc`) takes the save lock (`0x28df230e`), then D (`0x28df235a`), around `0x28df2234`, which parses (`0x28deb4e8` → the parser at `0x28deb862`) and runs both serializers' paths (`0x28df2060` at `0x28df2276`, `0x28df2148` at `0x28df228c`); D is let go at `0x28df236a`. `0x28df2038` (HX Edit's command at `0x28e1c1c2` → `0x28df03a8`) takes D alone (`0x28df2044`, let go at `0x28df2056`) around `0x28df1fa4` → `0x28deb1f4` → the parser at `0x28deb34a`. These are the parser's only direct callers. The save `0x28df25a4` above is the one path found that serializes with no D around it.
  - The record defaults `0x28de14b4` take the manager lock (`0x28de14c2`) and then D (`0x28e04044` at `0x28de150a`, D at `0x28e04066`), the opposite order to select's; Copy/Swap Snaps' swap runs them in the key task with no D around (`0x28dcc566` → `0x28de1888` → `0x28de14b4`). The settings lock `0x2845ee88` comes in both orders too: select reads settings under D (`0x28de2ffe`, the getter `0x28e1f844` takes the lock at `0x28e1f852`), and `0x28e1f458` holds the lock (`0x28e1f47e`) around the store write `0x28e1f0d8`, which takes D through `0x28e04a2c` (`0x28e04a4e`, only in state 2, as select).
- **Select's posts to HX Edit** [verified offline] (disassembly, 2026-11-20; the count's and the posts' stock code run in unicorn by `tests/test_more_snapshots.py`): after its index check (an index above 2 leaves at `0x28de2fe4` and returns -0x2e, `0x28de36e2`, having posted nothing) select posts `0x44113` with no data (`0x28de3006`; `0x28de3436` on a reselect). Writing the footswitch entries (`0x28de3244` → `0x28de672c`) posts `0x24112` with `{switch, byte, old, new}` (`0x28de678e`) for each byte of the footswitch manager that changes, under select's D. Its last post, `0x2102` (`0x28de32d8`, `0x28d99888`), comes after it lets D go (`0x28de32d4`). The error exits post `0x44118` with no data and no `0x2102`; those through `0x28de326c` (a controller entry that failed: `0x28de3120`, `0x28de3152`, `0x28de34a4`, `0x28de34e0`, `0x28de3556`) take one off the count below first, the others (straight to `0x28de3272`) do not. An unused record is filled with the count up (`0x28de3294`, down at `0x28de32c2`), so its `0x44115` (`0x28de3508`) is dropped, and nothing else is applied: the record copies the sound heard. These events reach HX Edit's notify listener and nothing else ([usb-editor.md](usb-editor.md#notify-the-events-hx-edit-hears-verified-offline-disassembly)); the rings and labels are refreshed by other paths ([tempo-and-leds.md](tempo-and-leds.md)), the request after a select is `0x28df0684` (`0x28de32de`, after the post of `0x2102`): it builds `{2, 0x0d, its argument}` for `0x28df1bf4`, which calls the callback the boot registered for all seven kinds, `0x28d93d68`, `0x28e1e704(0, msg, 0x14)`. That queue's push `0x28e1e884` takes its room from a heap (`0x28e1e5b4`, under the heap's own lock) and drops the message when there is none (`0x28e1e8b0`), so it never waits for a reader, and it reads no count [verified offline]. That the message reaches the footswitch handler's `0x28dd25d8`, whose `0x0d` case refreshes the rings (`0x28dd26cc`), was not traced [hypothesis].
- **The count that holds those posts back** [verified offline]: `0x28d99728(on)` adds one to the word at `0x281caa8c` (on 1) or takes one off unless it is 0 (on 0), with a load, an add and a store and no lock. While it is above 0, `0x28d99820(event, data)` and `0x28d99888()` return 0 before they take an event or a block. Nothing else reads it: its loads are those three and the set-up `0x28d99740`, which zeroes it. Who puts it up: the boot (`0x28d96a06`..`0x28d96a4a`, `0x28d96a76`..`0x28d96f64`), select (above), the load's controller and footswitch rebuilds `0x28de039c` and `0x28de05c8` (from `0x28deb5d4`, `0x28deb23c`, `0x28deb6f6`, under the load's D), and `0x28de0468` (`0x28dbcb0e`) and `0x28de0540` (`0x28dbba34`). Those four take it down and then post one `0x2102`: stock tells HX Edit of a batch of changes with one event, not one each. `0x28de0468` and `0x28de0540` change it without D around the change (they take D only inside, for each item, through `0x28dddc98` → `0x28e02a24`), so their load-add-store can interleave with select's in another task, and so can select's own outside state 2, where it takes no D [hypothesis: a lost update would hold HX Edit's events back until a restart, or let a batch's or a select's out early, inside a D held around it; not seen].
- **Presets store snapshots as msgpack**, with integer keys. The parser `0x28de42c4(manager, buf, len, ...)` resets the records, then reads an array of snapshot maps with **no bound on its count**: a preset with more than three would overwrite the manager's fields after the records on stock firmware. The writer `0x28de3c9c(manager, stream, flag)` writes a fixed `0x93` (three), takes no lock, and has two callers (`0x28dea9fa`, `0x28deaf36`).
- **The snapshot icon** [verified offline]: the top view's image widget at `0x2812aae0 + 0x308` (node `+0x32c`), top left (262, 237), anchor 6, 52x35: a camera with the number in a circle (inside x 278..304, y 204..232; the digit white, rows 208..228). It shows `Icon_Snapshot1..3` (table `0x28e3add4`) or `Icon_Snapshot1Red..3Red` (`0x28e3adc8`, the outline red, the digit still white) by the current snapshot (`0x28dc9edc`, `0x28dca276`). The image store has `Icon_Snapshot4` (the XL's) but no 5 or 6. **[verified on unit]** The footswitch names are not a reliable bank marker after a flip.

How presets store them: [presets.md](presets.md). Six snapshots: [features/more-snapshots.md](../features/more-snapshots.md).
