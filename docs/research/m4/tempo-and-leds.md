# Tempo, the stock beat and the LEDs [verified offline]

The tempo settings, the tap tempo screen, the footswitch LEDs and the stock beat that blinks the TAP ring. Status tags as in [conventions.md](../conventions.md).

- The tempo is a Global Setting: **ID 14** Tempo Select (0 Snapsht, 1 Preset, 2 Global), **ID 15** Global BPM, **ID 16** Preset BPM. The stock code always picks the BPM setting as `ID 14 == 2 ? 15 : 16` (tap `0x28d9bfa8`, tempo screen `0x28d91368`).
- `GET_VALUE(15 or 16, out)`: `[out]` type byte 3 (float), `[out+4]` the BPM as a float. The tap tempo stores 60e6 / (mean of the last 8 intervals in µs), clamped to 40..240, with the settings setter `0x28e1f8f4(ctx, id, &value, 3)`.
- The tap tempo screen (constructor `0x28dcc8d4`, title `Tempo`, rows `0x28d91248`/`0x28d911a8`) shows the BPM from `0x28e04aa0(0x28d92a98(), out)`: a 5-byte record `{byte, float}` from the current preset's object (`+0xb09` when its byte `+0xb08` is set, else `+0xb0e`), and `Extrnl` instead while the flag `0x28d9685c()` (byte `0x2812bd90`) is set. **[hypothesis]** That flag is external MIDI clock, and the record is the snapshot or preset tempo.
- **[hypothesis]** `GET_VALUE(16)` follows the current snapshot's tempo when Tempo Select is Snapsht.
- **Front panel LEDs** [verified offline]: three (0..2), the footswitch rings; footswitch k has LED k. `0x28d98f74(led, rgb)` sends a colour to the panel's LED controller (over 100 callers, every LED change); it starts `push {lr}; ldr r3,=0x281c90a4`. The driver keeps per LED a colour `0x281f35e0 + 3i`, a mode `0x281f35f8 + i` (0 off, 1 on, 2 blink; `0x28db8260(led, mode)`) and a half period `0x281f3608 + 4i` (`0x28db8138(led, period)`). The LED task `0x28db7f04` (started from `0x28db843c`) loops with `0x28e24c58(1000)` (the ROM sleep `0x10000830` waits (us + 9) / 10 ticks of 10 µs, so a turn takes 1 ms plus its work) and toggles mode-2 LEDs at `0x28db7f9a`. **[verified on unit]** The TAP footswitch's blink does not come through that toggle (a hook there never saw it) but does go through the LED send, and it keeps time with a metronome.
- **The stock beat** [verified offline]: a task loop from `0x28d9bdfc` sleeps 1 ms (`0x28e24c58(1000)`), then reads the µs clock `0x28da6458()` into `0x281cd070`. While its enable byte `0x281ccc48` is set and footswitch 3 (`[0x28128a78]`) is TAP, it turns the beat once more than half the period `0x281ccc44` (whole ms, set by `0x28d9bef8`) has passed since the last turn `0x281cd074` (µs; `(now - last) / 1000 > period / 2`). At each turn it moves the last turn on by `period * 1000 / 2`, flips the phase byte `0x281ccc49`, and sets LED 2 on (`0x28db81fc` colour, then `0x28db8260(2, 1)`) or off (`0x28db8260(2, 0)`). In every other case it sets the last turn to now, so **without a TAP footswitch the stock keeps no beat**. The period is `u32(60000.0f / tempo)` (`0x28dd0af6`, literal `0x476a6000`). `0x28dd0ab8` skips all of this while the byte `0x28128260` is 5.
- **Who sets the beat going** [verified offline]: the LED refresh's TAP case (`0x28dd0d40`, when its second argument is non-zero) and a tempo setting's change (below) call `0x28dd0ab8(obj, k)`, which with Tap Tempo LED (setting 26) on calls the period setter `0x28d9bef8(period)` and the enable `0x28d9bf2c()`; with it off it turns ring k off and clears the enable (`0x28d9bf8c`). The period setter puts LED 2 in the driver's blink mode (`0x28db8260(2, 2)`, `0x28db8138(2, period)`) whenever the period changes or the beat is off, whatever FS3 is. The TAP case then leaves the refresh's loop (`b 0x28dd0ba0`). The beat's own sites: the "is FS3 TAP" reads `0x28d9be3a`, `0x28d9be4c`, the on-turn's `0x28d9be92`, the off-turn's `0x28d9beba`. The [Tap command](../features/tap-command.md) owns them to blink its rings.
- **A tempo setting's change** [verified offline]: the event handler `0x28dd25d8` takes a setting change (event byte +5 `0x19`, the setting ID at +8; its jump table at `0x28dd272c` sends 14, 15 and 16 to `0x28dd276a`). That case walks footswitches 0..2 (`0x28d9607c()`, read at `0x28dd276c`) and calls `0x28dd0ab8(obj, k)` for the first one that is TAP (`0x28dd27a6`); with none it does nothing. [verified on unit] External MIDI clock comes this way: with FS3 TAP the ring follows the clock, and a Tap command's ring follows it only with the [Tap command](../features/tap-command.md)'s `tc_setting` there.
- **No TAP footswitch** [verified on unit]: in Preset and Snapshot footswitch modes no footswitch is TAP, so no ring blinks (as on stock).
- **The TAP ring's colour** [verified offline]: an LED colour is `0x00BBGGRR` (the setter `0x28db81fc(led, colour)` stores it as bytes R, G, B). The stock beat lights the TAP ring with the word at `0x28e280b0` (`0x0300ff`, red) through the literals `0x28d9bee0` and `0x28d9bf84`, calls at `0x28d9bea8` and `0x28d9bf6e`; while `0x28d9685c()` is set it takes `0x28e280ac` (`0xff3200`, blue) instead (`0x28d9bed0`, `0x28d9bf7a`). The footswitch LED refresh `0x28dd0b3c` sends a TAP footswitch to `0x28dd0ab8`, which reaches the same `0x28d9bf2c`.
- **The stock LED palette** [verified offline]: `0x28dd8030(_, i, lit)` returns colour i (1..10) as `0x00BBGGRR`, lit when lit is 1 and a dim shade when it is 0 (red `0x0c0002`; run in unicorn). Lit: 1 `0xceff6b`, 2 `0x0300ff` (the TAP red), 3 `0x002dff`, 4 `0x00afd0`, 5 `0x00ff84`, 6 `0x00ff06`, 7 `0x80ff00`, 8 `0xff3200`, 9 `0xff0032`, 10 `0x2800ff`. The footswitch LED refresh calls it dim at `0x28dd0be6` and lit at `0x28dd0dc4`.
- **Preset mode's ring** [verified offline]: the LED refresh's function-13 case lights only the current preset's ring, red from the word `0x28e3c4a0` (literal `0x28dd0f40`), and turns the others off; see [features/preset-color.md](../features/preset-color.md).
- **Snapshot mode's rings** [verified offline] (disassembly; the built refresh run in unicorn by `tests/test_more_snapshots.py`): the refresh's function-14 case (`0x28dd0bae`, from the jump table at `0x28dd0b84`) reads the current snapshot (`0x28de3750`, at `0x28dd0bb2`). The current one's ring is on (`0x28db8260(k, 1)`) in its colour lit (`0x28de2f80` at `0x28dd0daa`, `0x28dd8030(_, colour, 1)` at `0x28dd0dc4`), or in white (`0x28e3c4a8`, `0xceff6b`) for colour 0. Another's (its colour at `0x28dd0bc2`) is off for colour 0 or with LED Ring Brightness (setting 25) at 0, else dim in its colour (`0x28dd0be6`), on. Before the function byte, a footswitch whose controller k + 6 has type 14 in Stomp mode (setting 21 = 0) goes to `0x28dd06c8`, which compares the snapshot it selects with the current one (`0x28dd07c6`). The refresh takes the footswitch handler's object (`0x28128a80`) and a flag only the TAP case reads; the message handler `0x28dd25d8` calls it with 1 (`0x28dd26a0`) or 0 (`0x28dd26cc`, on its message `0x0d`) and the handler's registration `0x28dd27fc` twice (`0x28dd2880`, `0x28dd2936`), each only when the tuner is not open (`0x28dd2692`, `0x28dd26be`, `0x28dd2874`, `0x28dd2928`). Stock calls it from 16 places: those four, `0x28dd0f44`, five in `0x28dd10c0`, `0x28dd14a0`, the deferred dispatch `0x28dd18b0` and four in the footswitch event handler `0x28dd1978`; the tuner test was read only for the four. [More snapshots](../features/more-snapshots.md) owns the two reads at `0x28dd0bb2` and `0x28dd0bc2`.
- **Tap Tempo LED** (setting 26) is read at only two places that decide to blink: `bl GET_VALUE` at `0x28d9c116` (the tap core) and `0x28dd0ae2` (in `0x28dd0ab8(obj, k)`, k the TAP footswitch).
- **Microsecond clock** [verified offline]: `0x28da6458()` (`0x28da37ac(1)`, a hardware timer register) is what the tap tempo times taps by (BPM = 60e6 / interval).
