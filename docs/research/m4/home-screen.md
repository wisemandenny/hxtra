# Home screen, views and widgets [verified on unit]

The Home view and its divider, the top view, the Edit view, the widget types, and how a paint reaches the framebuffer. Status tags as in [conventions.md](../conventions.md).

## The Home view and the divider

- The Home view is a static object at `0x2812a05c` (returned by `0x28d960f4`).
- The divider is four 80 px segment widgets at `0x2812a594 + 0x1c*k` (k = 0..3). Layout function `0x28dc87cc` resets them to the stock look on mode change.
- Stock: the selected segment is white and 2 px, the others grey `0x666666` (a literal at `0x28dc8b58`) and 1 px. `tools/patch_divider.py` makes the whole divider 2 px green by patching three sites (`0x28dc8808`, `0x28dc8b22`, `0x28dc8b58`). Verified on the unit.

## Widgets

- **Rectangle widget fields** [verified offline] (ROM `setSize` `0x10001ae0`, `setPos` `0x10001a6c`): words `[0]` colour, `[4]` x, `[8]` y, `[0xc]` w, `[0x10]` h, byte `[0x15]` visible, `[0x18]` node.
- Widget setters (PLT stubs, Thumb): `setColor 0x28e24b98` (r0 = widget, r1 = `0xRRGGBB`, black = 0); `setSize 0x28e24b28` (r0 = widget, r1 = w, r2 = h). Both take a mutex and invalidate, so they are not free to call at high rate; cache and call only on change.
- From the ROM bodies (segment 1) [verified offline]: a widget is `[0]` colour, `[4]` position, `[0xc]` size, `[0x15]` visible, `[0x18]` node. `setColor`, `setSize` and `setPos` given the value the widget already has do nothing. `setColor` (`0x10001a3c`) stores a new colour and marks a visible widget's node dirty (`[node+0x24] = 1`). `setSize` (`0x10001ae0`) and `setPos` (`0x10001a6c`) store a new value, write the node's damage rectangle (`0x10003284`: the old and new rectangles, and the damage already there if the node is dirty; only the new one for a hidden widget whose node is clean) and mark a visible widget's node dirty. `0x28e24b00` is `setVisible(w, v)` (`0x10001ba4`; the image and text widgets' `0x10001e3c` and `0x10002394` alike): it stores v and marks the node dirty even when the widget is already visible; only a hidden widget kept hidden is left alone. Nothing repaints until **`0x28db8508(full, partial)`** (96 callers; the layout ends with `(0, 1)`), which sets dirty flags `0x281f3728`/`0x281f371c` under mutex `0x281f3720` and signals `0x281f3714`, waking the UI thread.
- The ROM mutex (`0x10000500`) fails instead of blocking when `CONTROL` is 0 (interrupt or pre-RTOS), so the setters and the redraw request degrade rather than hang in such contexts.
- **Creating widgets [verified offline]**: the Home constructor `0x28dc91d0(home)` (called at boot by `bl` at `0x28d96c44`) builds each divider segment as: `0x28e24988(widget, node)` (init: zero both, visible = 1, `[widget+0x18] = node`; a node is 0x28 bytes of plain memory, the stock ones at `home+0x9e0+0x28*k`), `0x28e24a18(widget, 6)` (layer), `setColor`, `setSize`, `0x28e24af0(widget, x, y)` (setPos; x from a table at `0x28e3ab84` = 0, 80, 160, 240; y = 0x77), `setVisible(widget, 1)`. No global list: a widget appears only if a paint function handles it, in two passes [verified offline]: **erase** `0x28e24b40(fb, fb, widget)` (ROM `0x100019b4`: if the node is dirty, fill the node's damage rectangle with black, then update the node's geometry) and **draw** `0x28e24b58(fb, fb, widget)` (ROM `0x100019f0`: if dirty and visible, fill the widget's rectangle in `[widget+0]`, then mark it clean). The stock paint erases every widget before it draws any. The node's damage rectangle (`0x10003284`) [verified offline] is the union of the old and new rectangles only when the old one has a non-zero size; an old rectangle of zero width or height is dropped, so a zero-sized widget that moves damages only its new place. While the node stays dirty, each setSize and setPos adds to its damage. The erase fills the damage, then gives it the widget's width and height but keeps its corner, so it is the widget's own rectangle again only after an erase finds the node clean. A widget whose node is not dirty is not drawn again when another widget's erase fills over it, nor after the top view's clear (under Painting): the GR meter's lights beside the divider segments stayed black after the stock layout had sized the segments to 80 px (issue #185, [features/gr-meter-log.md](../features/gr-meter-log.md)).
- **Widget types** [verified offline] (`init` stub, then the size): rectangle (`0x28e24988`, 0x1c bytes); image (`0x28e24ab0`, 0x24 bytes: `[0]` image ID, `[0xc]`/`[0x10]` x, y, `[0x14]`/`[0x18]` w, h (from the image), `[0x1c]` anchor, `[0x1d]` visible, `[0x20]` node; setPos `0x28e24c68`, anchor `0x28e24aa8`, setImage `0x28e24c18`, setVisible `0x28e24a98`; erase `0x28e24b68`, draw `0x28e24a00`); text label (`0x28e249d0`, 0x30 bytes; erase `0x28e24c90`, draw `0x28e24c30`). Every type redraws only when its node's byte `[node+0x24]` is 1. The Home view's footswitch "labels" at `home+0x2b0..0x4a8` are image widgets; its 0x30-byte widgets at `home+0x64..` are the text.

## Painting

- **Footswitch labels** [verified offline]: `0x28dc853c(home)` rebuilds the three labels with `0x28dc7e80(home, k)`, which switches on footswitch k's function byte. Each label has two text lines (`home + 0x64 + 0x30k`, `home + 0xf4 + 0x30k`) and a switch icon (image widget `home + 0x3f4 + 0x24k`). The TAP case (`0x28dc7f7c`) sets both lines to `TAP/` and `TUNER` in `0xff0000` and the icon to `Icon_SwitchRed` (0x78). The stomp case colours them by the block's category record (`0x28d9e01c(cat, out)`: a 0x2c-byte record from `0x28e2815c`, name then lit and dim colours `0xRRGGBB`), and `0x28dc6e9c(colour)` picks the matching `Icon_Switch*` image (`Icon_SwitchWhiteOff` for a colour it does not know). The Home view is at `0x2812a0c8`.
- **Painting**: the UI loop (`0x28db7fxx..0x28db80e6`) paints the topmost active view of each of two view lists into one of three framebuffers (`0x25800` bytes each, 320x240 RGB565) in turn, then shows it. Paint return values are ignored. `0x100017e8(fb, x, y, w, h, colour, mode)` is the rectangle fill (colour `0xRRGGBB`, converted to RGB565).
- **Home paint**: `0x28dc8d38(ctx, home)`, registered at boot by `0x28db86bc(paint, 0x28dc9129, home)` from a literal at `0x28d96e28`. It takes the widget lock (`0x28e24970`) first and tail-calls the unlock (`0x28e24ae8`). The layout's divider segment width is the `movs r3,#0x50` at `0x28dc87fc`.
- **Framebuffer and fill** [verified offline]: the framebuffers are at `0x28d1ce98 + 0x25800 * k` (k = 0..2), column-major: pixel (x, y) is the halfword at `fb + 2 * (240 * x + y)`, which is why widget y counts up from the bottom. After each paint, a GPDMA list (`0x281f1f6c + 0x320 * k`, set up at `0x28db8336`) copies the painted buffer into the next, so pixels written straight into the framebuffer persist like widget pixels. The fill `0x100017e8(fb, x, y, w, h, colour, anchor)` places the rectangle by an anchor 0..8: column `anchor % 3` puts x at the left edge, the centre or the right edge, row `anchor / 3` puts y at the bottom edge, the centre or the top edge (so 4 = centred, 6 = rows `[y - h, y)`). It clips to 320x240.
- **The buffer on screen** [verified offline, disassembly]: the LCD controller is the LPC43xx one at `0x40008000` (`0x28d9f880` sets its `CTRL` power and enable bits, `0x18`, and its interrupt mask and clear, `0x1c` and `0x28`). `0x28d9f990(fb)` shows a buffer: it refuses an address not 8-byte aligned, then writes it to `UPBASE` (`0x40008010`). So `[0x40008010]` is the framebuffer the panel shows at that moment; the [screen mirror](../features/screen-mirror.md) reads it.
- **Two view lists** [verified offline]: `0x28db86bc(paint, handler, view)` appends a view to list A (head `0x281f35b8`), `0x28db8594(...)` to list B (head `0x281f3d2c`). Each loop (`0x28db802a..0x28db80c0`) paints one view of A, then one of B, into the same buffer: the first node from the head (nodes `[0]` flags, bit 0 active, `[4]` paint, `[0xc]` view, `[0x14]` next) that is active, and none if that node has no paint. A list is painted only when its flag is set: `0x28db8508(b, a)` sets `0x281f3728` (list B) from its first argument and `0x281f371c` (list A) from its second, and the loop clears both. So the layout's `(0, 1)` repaints list A alone. On the main screen, A's is the Home view (bottom half) and B's the **top view** `0x2812aae0` (constructor `0x28dca5e8`, paint `0x28dca358`, registered from the literal at `0x28d96d90`): preset number (y 0xed), preset name (y 0xc5) and the signal-flow row.
- **The top view's clear** [verified offline, disassembly; on the unit, a footswitch-mode change blacks out the whole GR meter at Top and Bottom]: on a change of setting 0x15 (the footswitch mode), the top view's handler `0x28dc9e38` sets `view[9]` to 0 and calls `0x28db8554` (`0x28dca04e`), then relayouts itself (`0x28dc9d74`, when `view[8]` is set) and asks for `0x28db8508(1, 1)`. `0x28db8554` clears the whole framebuffer to be painted next to 0 by GPDMA (a list at `0x281f28cc + 0x320 * k` that fills all 0x25800 bytes from the fixed word `0x281cf818`), under the lock `0x281f3d30` the paint loop holds while it paints. The UI task hands an event to the current view's handler first (the top view's for view 0, `0x28d95204`) and then to the current panel's (the Home view's for panel 1, `0x28d9521a`, when `[0x28128270+0x58]` is not 0, `0x28d95210..216`), so on the Home screen the Home view's handler `0x28dc8c80` runs the stock layout after the clear (`0x28dc8d24`; on the unit it did after every footswitch-mode change tried). The layout's setVisible marks the divider segments and the shown labels and icons dirty, so they are drawn again; a widget nobody marks stays black, as the GR meter's lights did (issue #185, [features/gr-meter-log.md](../features/gr-meter-log.md)). `0x28db8554` has 46 callers, among them the top view's showing (`0x28dca566`) and Preset mode's bank change (through `0x28dca2fc`).
- **Switching views** [verified offline]: the UI task's `0x28d93db4` takes the request word `0x2812d27c` (and clears it). Bit `0x1` switches to view `[0x2812bd93]` (0..9, table `0x28e25098`, 8 bytes each: the view's handle and its name: gPlayViewID 0, gEditViewID 1, gModelListViewID 2, gGlobalViewID 3, gSaveViewID 4, gTunerViewID 5, gGlobalEQViewID 6, gAlertViewID 7, gPresetListViewID 8, gCommandCenterViewID 9) and stores it as the current view `0x28128260`; bit `0x2` shows panel `[0x2812bd92]` (1..14, handles at `0x28e2505c`), the current panel at `0x28128258`. `0x28d96320(view)` and `0x28d9638c(panel)` store the byte and set the bit, and do nothing while `[0x2812b42c + 0x95a]` or `[0x2812a05c + 0x5c]` is set; `0x28d96134(view)` is 1 when it is the current view. The stock code calls them in pairs: Global Settings' Global EQ item (`0x28dce50e`) asks for view 6 then panel 8 (handle `0x2812952c`, the Global EQ view `0x281294cc`, entered and left by `0x28d9a494`), and the key listener `0x28dcfa00`, on a press of key 3 or 4 (**[hypothesis]** Home), asks for view 0 then panel 1, the Home view. Other bits each ask for one thing, e.g. `0x200000` the tuner (`0x28d96588`). Long press's GlobalEQ uses these ([long-press.md](../features/long-press.md)).
- **[hypothesis]** Calling these from the DSP-link thread during boot, before the Home view exists, is a candidate cause of a freeze after the loading bar. See the [GR meter log](../features/gr-meter-log.md).

## The top view and the Edit view

- **Block slots** [verified offline]: the top view's eight block slots are image widgets at `view+0x634+0x24*k`, centre-anchored (4) at x = 90 + 20k, y = 0x93, or 0x85 when the model says the slot is on the second path (`0x28dd2a74`, model `0x2812c590` from `0x28d960ac`). An empty slot is hidden; the image comes from the block's category and on/off state (table `0x28e3abdc`, set at `0x28dc992c..`). The paint updates the slots only while `view[9]` is 0.
- **Edit view** [verified offline]: `0x28128270` (list A, constructor `0x28dc1454`, generic paint `0x28d947c8` from the literal at `0x28d96e38`: it calls `0x28dc566c(fb, fb)`, ignoring its view, and nine other list A views are registered with it; the bottom half's parameters) and `0x281282f8` = `0x28128270 + 0x88` (list B, constructor `0x28dc2b48`, paint `0x28dc27f8`, registered from the literal at `0x28d96da0`; getter `0x28d960bc`) are the Edit view. The top half's eight block slots are image widgets at `0x281282f8+0x4a4+0x24*k`, centre-anchored at x = 41 + 34k, y = 0xa5 with no split (`0x28dc183c`; a screen capture shows the row centred there), else 0xb5, or 0x95 on the second path (layout `0x28dc1634`), hidden when empty, images from table `0x28e3a8c0` (set at `0x28dc1a86..`). Its paint draws them whatever the mode.
- **Edit view, free rows** [verified offline]: the divider is rows 118..119 (y from the bottom), the bottom half's block title rows 89..111; with no split the block row is rows 153..176, so rows 120..152 are free; with a split, rows 120..136.
- **Selected block** [verified offline]: `0x28df0280(&path)` returns the selected block's ID (a word at `+0xed4` of a state object, the path byte at `+0xed8`) under its own lock; the Edit view's layout reads it at `0x28dc1902` before taking the widget lock. IDs map to block records as in [dsp-cost.md](dsp-cost.md).
- **Edit view** [verified offline]: the top strip has the block title at the left (labels `+0x5c` at x 7 and `+0x8c` at x 0x45, top edge y 0xea) and a 6x9 marker (`+0x704`, image 0x43) placed 6 px after the title (`0x28dc2026`); the top right corner is free unless the title is very long.

Text widgets and fonts: [text-and-fonts.md](text-and-fonts.md). Image records: [formats/image-store.md](../formats/image-store.md).
